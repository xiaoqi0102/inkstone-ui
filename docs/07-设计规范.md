# 一、基础规范（Foundation）
## 1.1 色彩
全为 **oklch**，唯一源头 `src/styles/tokens.css`：浅色在 `:root`，深色在 `html.dark, .dark`。

> **色温铁律（这套配色成立的关键）**：全部中性色（底 / 卡 / 静默 / 描边 / 次级 / 抬升）色相统一落在**暖带 55°~95°**；品牌蓝与图表冷色统一落在**冷带 248°~258°**。
> 一旦把 `--muted` / `--border` 这类中性色也调成冷色，卡片内的进度轨、分隔线、输入框描边就会和暖卡底「冷暖咬合」发脏。**只让品牌蓝当唯一的冷点。**

### 1.1.2 文字对比度下限
| 内容 | 用什么 | 下限 | 说明 |
|---|---|---|---|
| 正文 / 可读信息 | `text-foreground` | ≥ 7:1 | 目标值。表格数据、表单值、说明正文 |
| 次要文字 | `text-muted-foreground` | ≥ 4.5:1 | 仅标签 / 单位 / 脚注 / 时间戳；**不得承载必读内容** |
| 大号文字（≥ 20px，或 ≥ 18.66px 粗体） | `text-muted-foreground` 可用 | ≥ 3:1 | 如 `StatCard` 的单位 |
| 禁用态 | `disabled:opacity-50` | 豁免 | 但必须与可点态视觉可辨，且不得作为唯一信息来源 |
| 占位符 | `placeholder:text-muted-foreground` | 豁免 | 永不可替代 `FieldLabel` |

**铁律：颜色不是唯一信息载体。** 状态色必须同时有文字或图标——`Badge` 写「失败」而不只是红点；`StatCard` 的 trend 带 `↑` / `↓`；必填不能只靠红框。
## 1.2 字体与数字
### 1.2.1 字号阶梯（真实档位）
系统字体栈，不引外部字体；无自定义 `--text-*`。

| 类 | 值 | 用在哪 | 为什么 |
|---|---|---|---|
| `text-[10px]` / `text-[0.8rem]` | 10 / 12.8px | `MetricTabs` 的 badge 计数 / `Calendar` 星期行 | 极次要角标不抢字重；日历网格固定密度 |
| `text-xs` | 12px | 卡片标签、说明、`Badge`、`FieldError`、代码块、请求详情字段表、`Tooltip` | 一切「注解性」文字 |
| `text-sm` | 14px | **界面默认正文**、`Input`、`Button`(default)、`CardDescription`、`SelectItem`、`TabsTrigger`、`Toaster` | 高密度后台的基线字号 |
| `text-base` | 16px | `PageHeader` 标题、`Button size="lg"` | 区块标题，比正文重一档 |
| `text-lg` | 18px | 按需强调（核心件未固定使用） | — |
| `text-2xl` | 24px | `StatCard` 数值 | 统计卡主角 |
| `text-3xl` | 30px | `AppShell` 页面名（`mt-1 truncate text-3xl font-bold`） | 一屏唯一最大字 |

**字重**：页面名 `font-bold` → 区块 / 卡片标题 `font-semibold`（`PageHeader`、`CardTitle`、`StatCard` 数值、`MorphingDialogTitle`、`TabsTrigger` 激活）→ 字段名 / 按钮 / 徽标 / 导航 `font-medium` → 正文默认 400 → 说明 `font-normal`（`FieldDescription`、`FieldError`）。
### 1.2.2 数字一律 tabular-nums
**凡数字宽度会变化的文本，必须 `tabular-nums`**（已落地：`StatCard` 数值与趋势、`MetricTabs` badge）。三个必用理由：① **统计卡** `AnimatedNumber` 补间时每帧宽度都在变，非等宽会把旁边元素推着抖；② **日志耗时** `12ms` → `345ms` 位宽跳变让整列错位，扫读分不清列；③ **金额与计数** 一列金额用比例数字则小数点无法对齐，肉眼比对金额基本失效。其他等宽需求用 `font-mono`（`CodeBlock`、`JsonViewer`、`RequestDetail` 的 `mono: true`），两者可叠加。
### 1.2.3 金额与计数统一走 `formatMoney` / `formatCount`
**禁止在页面里手写 `toFixed` / 千分位拼接。** 这些函数都返回 `{ raw, formatted }`：`raw` 给逻辑，`formatted` 给展示。

| 函数 | 阈值 | 输出 | 用途 |
|---|---|---|---|
| `formatMoney(n)` | 1e9 / 1e6 / 1e3 | `$` → `K$` → `M$` → `B$`，如 `1.23M$` | 金额（USD） |
| `formatCount(n)` | 1e9 / 1e6 / 1e3 | 空 → `K` → `M` → `B`，如 `1.23M` | 次数 / 条数 / token 数 |
| `formatTime(ms)` | 86400000 / 3600000 / 60000 / 1000 | `d` → `h` → `m` → `s` → `ms` | 耗时 |
| `withThousands(n)` | — | `1,234,567` | 需要精确值（明细、导出） |
| `truncateMiddle(text, head=60, tail=30)` | 超长才截 | `头…尾` | 日志单行预览（比纯 head 信息量大） |

**值 / 单位分开渲染**（`StatCard` 的做法，其余照抄）：`<StatCard value={c.formatted} unit="次" />`。两个理由：① `1234` 与 `12.3` 两种量级的卡片**视觉重量一致**；② 数值补间滚动时单位不动，页面不抖。**统一保留 2 位小数**（`formatNumber` 内 `.toFixed(2)`）——不要为个别卡片改成 1 位，否则同屏数字对不齐。
## 1.3 间距与栅格
### 1.3.1 基准与档位
`--spacing: 0.25rem`（4px），所有间距都是它的整数倍。**只准用下列档位**：

| 档位 | px | 用在哪（真实出处） |
|---|---|---|
| `gap-0.5` / `gap-1` | 2 / 4px | `MetricTabs` 容器内、`Badge`、`PageHeader` 动作区、`DockNav` 移动端项间 |
| `gap-1.5` | 6px | `CardHeader`、`ChartTooltipContent`、`TabsTrigger` |
| `gap-2` | 8px | `Field`（标签与控件）、`Button` 基类、`StatCard` 表头、`SelectTrigger`、`Label` / `FieldLabel` |
| `gap-3` | 12px | `PageHeader`、`RequestDetail` 块间、`AccordionTrigger`、`Tabs` 容器、`DockNav` 桌面端 |
| `gap-4` | 16px | `Card` 基类、`FieldSet`、`TabsList variant="line"` |
| `gap-5` | 20px | `FieldGroup`（字段行之间） |
| `gap-6` | 24px | `AppShell` 桌面端栏间（`md:gap-x-6`） |

**不要写 `gap-7` / `gap-9` 这类中间档**——间距系统一乱，整套节奏感就没了。要更大间隔用 `mt-*` / `space-y-*` 表达「分组」，而不是平白加 gap。
### 1.3.2 卡片内边距约定
| 部件 | 内边距 | 出处 |
|---|---|---|
| `Card` | `py-5`（无左右 padding，左右交给子件） | `card.tsx` |
| `CardHeader` / `CardContent` / `CardFooter` | `px-5` | `card.tsx` |
| `CardHeader` 内间距 | `gap-1.5` | `card.tsx` |
| `StatCard`（覆盖） | `py-4 gap-2`，内部行统一 `px-5` | `StatCard.tsx` |

**不要在外层再包 padding wrapper**；要更紧 / 更松的卡，用 `className="py-4"` 覆盖 `Card` 本身，不要改内部各件的 `px-5`——那会让同屏卡片左右边缘错位。
### 1.3.3 页面内容区宽度与断点
| 项 | 真实值 | 出处 |
|---|---|---|
| 内容区最大宽度 | `max-w-6xl`（72rem / 1152px），`mx-auto` 居中 | `AppShell` |
| 页面内边距 | `px-3` / `md:px-6` | `AppShell` |
| 外壳高度 / 顶栏纵向边距 | `h-dvh` + `overflow-hidden`；`my-3` / `md:my-6` | `AppShell` |
| 导航吸附位置 | `md:top-30`（7.5rem） | `DockNav` |
| 断点 `sm` / `md` / `xl` / `2xl` | 640 / 768 / 1280 / 1536px，与 Tailwind v4 默认一致 | `VirtualizedGrid.BREAKPOINTS` |
| 断点 `lg` | **960px**（**与默认 1024px 不一致**） | 同上 |

> ⚠ `VirtualizedGrid` 的 `lg` 是 **960px**，而 CSS 里 `lg:` 前缀仍是 1024px——**JS 列数与 CSS 断点在这个档位不一致**（源码既有行为）。本仓库**没有 `tailwind.config.js`**，主题全在 `globals.css` 的 `@theme inline`，不要去找配置文件改断点。
## 1.4 圆角与描边
### 1.4.1 `--radius` 派生链
`--radius: 0.5rem`（8px），在 `@theme inline` 中派生：

| 类 | 计算 | 值 | 用在哪 |
|---|---|---|---|
| `rounded-sm` | `calc(var(--radius) - 4px)` | 4px | 极小内嵌块 |
| `rounded-md` | `calc(var(--radius) - 2px)` | 6px | `TooltipContent`、`MetricTabs`、`SelectTrigger` / `SelectItem`、`TabsTrigger`(default)、`PopoverContent`、`Calendar` 单元格、`AccordionTrigger` |
| `rounded-lg` | `var(--radius)` | 8px | **`Input`、`Button`、`CodeBlock`、`JsonViewer`、`SelectContent`、`TabsList`、图表 tooltip** |
| `rounded-xl` | `calc(var(--radius) + 4px)` | 12px | **`Card`** |
| `rounded-2xl` | `calc(var(--radius) + 8px)` | 16px | `DockNav` 导航项与两个滑块、Logo 容器 |
| `rounded-3xl` / `rounded-full` | Tailwind 固定档（非派生） | 24px / 9999px | `DockNav` 胶囊外壳、`VirtualizedGrid` 顶部；`Badge`、`Switch` 与 Thumb、`Progress`、`MorphingDialogClose` |

**决策顺序**：① 控件（按钮 / 输入）→ `rounded-lg`；② 容器（卡片 / 面板）→ `rounded-xl`；③ 浮层（tooltip / 下拉 / 日历）→ `rounded-md`；④ 导航 → `rounded-2xl`（项）/ `rounded-3xl`（壳）；⑤ 胶囊状态物（徽标 / 开关 / 进度）→ `rounded-full`。
**嵌套硬规则**：外层圆角 > 内层圆角（`Card rounded-xl` 里放 `Button rounded-lg`）。内外同值时接触边会出现「圆角溢出」，看起来像没对齐。
> 唯一允许的任意值圆角：`Checkbox` 的 `rounded-[4px]`——它只有 16px 见方，套派生链会圆到看不出方形语义。
### 1.4.2 `border` 与 `border/50`
| 写法 | 场景 |
|---|---|
| `border border-border` | **容器与外框**：`Card`、`Input`、`CodeBlock`、导航胶囊、`Button variant="outline"`、`PopoverContent`、`SelectContent`、`AccordionItem` 下边线 |
| `border-border/60` | **容器内部的次级分隔**：`CodeBlock` / `JsonViewer` 标题栏下边线、JSON 树层级缩进竖线 |
| `border-border/50` | **浮层描边**：`ChartTooltipContent` |
| `border-destructive/25` | `Button variant="destructive"` 未悬停态 |
| `border-primary/30` | `Card interactive` 的 hover 态 |

判据：**外轮廓用实描边，容器内部分隔线一律降到 60% 以下**——容器内部再来一条等粗实线会被当成「两个容器」，层级就糊了。独立分隔区段用 `Separator`（`bg-border` 的 1px 元素），不要手写 `<div className="border-t" />`。
## 1.5 阴影
### 1.5.1 档位与真实值

| 令牌 | 真实值 |
|---|---|
| `--shadow-2xs` / `--shadow-xs` | `0 1px 3px 0px hsl(0 0% 0% / 0.05)` |
| `--shadow-sm` / `--shadow` | `0 1px 3px 0px hsl(0 0% 0% / 0.10), 0 1px 2px -1px hsl(0 0% 0% / 0.10)` |
| `--shadow-md` | `0 1px 3px 0px hsl(0 0% 0% / 0.10), 0 2px 4px -1px hsl(0 0% 0% / 0.10)` |
| `--shadow-lg` | `0 1px 3px 0px hsl(0 0% 0% / 0.10), 0 4px 6px -1px hsl(0 0% 0% / 0.10)` |
| `--shadow-xl` | `0 1px 3px 0px hsl(0 0% 0% / 0.10), 0 8px 10px -1px hsl(0 0% 0% / 0.10)` |
| `--shadow-2xl` | `0 1px 3px 0px hsl(0 0% 0% / 0.25)` |

> `2xs` 与 `xs` 同值、`sm` 与 `shadow` 同值（历史取值）。实际可用的是四段梯度：`xs` → `sm` → `md`/`lg` → `xl`/`2xl`。
### 1.5.2 用哪档（真实出处）
| 场景 | 档位 | 出处 |
|---|---|---|
| 卡片静止 / 表单控件静止 | `shadow-sm` / `shadow-xs` | `Card`；`Input`、`SelectTrigger` |
| 滑块 / 开关 / 选中项的实体感 | `shadow-sm` | `Switch` Thumb、`MetricTabs` 激活滑块、`TabsTrigger`(default) 激活 |
| 主按钮 / 主 CTA 渐变按钮 | `shadow-sm` / `shadow-md` → hover `shadow-lg` | `Button` default / `gradient` |
| 卡片悬浮 / 拖拽中的项 | `shadow-lg` | `Card interactive`（`hover:shadow-lg`）、`SortableList` |
| 下拉 / 气泡浮层 | `shadow-md` | `SelectContent`、`PopoverContent` |
| 图表 tooltip | `shadow-xl` | `ChartTooltipContent` |

**决策规则**：静止 = `sm`（卡片）/ `xs`（控件）；可交互要「浮起来」= `lg`；**只有浮层用 `xl` 及以上**。
### 1.5.3 禁用 Tailwind 默认 `shadow-md`
**规矩：禁止手写 `shadow-md` / `shadow-2xl` 等未经本库覆盖的档位。** 原因：本库在 `@theme inline` 里把这些名字**重定义成了上面那套自定义值**，所以库内引用安全；一旦在库外环境（或没引 `@theme inline` 的地方）使用就会退回 Tailwind 默认值——那套在深色主题下发灰、对比度不匹配。

```tsx
// ✅ shadow-sm 静止 / shadow-lg 可交互浮动 / shadow-xl 浮层
// ❌ <div className="shadow-md" />  ← 库外会退回 Tailwind 默认值
```

> 例外说明：`SelectContent` / `PopoverContent` 源码里确实写了 `shadow-md`——它们依赖 `@theme inline` 的重定义。**在库外复刻这两处时换成令牌**：`className="[box-shadow:var(--shadow-md)]"`。自定义阴影一律用 `var(--shadow-*)`，不要手写 `0 4px 6px rgb(0 0 0 / .1)`。
## 1.6 动效
### 1.6.1 时长变量
| 令牌 | 值 | 适用场景 | 真实出处 |
|---|---|---|---|
| `--duration-fast` | `150ms` | hover 颜色 / 亮度、按下（`active:scale`）、导航项颜色 | `Button` 基类、`DockNav` 项 |
| `--duration-base` | `200ms` | 图标交叉淡换、卡片悬浮上抬、`AccordionTrigger` 箭头旋转 | `CopyButton`、`Card interactive`、`AccordionTrigger` |
| `--duration-slow` | `300ms` | 滑块 / 指示器位移、弹窗进场、页面名切换 | `DockNav` 两滑块、`Progress` 填充、`AppShell` 标题 `duration: 0.3` |
| `--duration-slower` | `350ms` | 悬浮滑块淡入（比位移慢一点，避免「啪」地出现） | `DockNav` 悬浮滑块 `duration-350 ease-linear` |

**其他固定时长（已定型，别乱改）**：数字补间 `800ms` `easeOut`（`AnimatedNumber` 默认）；弹窗形变 `spring { bounce: 0.2, duration: 0.4 }`（`MetricTabs` 滑块、`MorphingDialog` 推荐值）。
### 1.6.2 缓动与位移约定
| 类型 | 缓动 | 位移上限 |
|---|---|---|
| hover / 颜色 | `ease-out` | 0（只变色 / 亮度） |
| 滑块位移 | `ease-out`，淡入 `ease-linear` | 位移 = 步长，不改尺寸 |
| 卡片悬浮 | 默认 | `-translate-y-0.5`（**2px**） |
| 页面名切换 | 默认 | `y: 32px`（进出反向，按导航顺序） |
| scale 反馈 | 默认 | hover **≤ 1.1**（导航项 `hover:scale-110`）、按下 `active:scale-95` / `scale-[0.98]` |

微交互位移**不超过 4px**；结构性位移（页面切换、弹窗）才允许 32px 量级。**scale 上限 1.1**，超过就是「廉价放大」。
### 1.6.3 必须有 / 禁止
**必须有**：① 每个可点元素都有 hover 反馈，≤ 150–200ms；② 展开收起有过渡（`JsonViewer` / `CodeBlock` / `Accordion` / `MorphingDialog`，不能瞬切）；③ 数值变化走 `AnimatedNumber`（800ms），让用户感知「刚更新」；④ 页面切换给方向（`AppShell` 的 `direction`）；⑤ 关键过渡加 `motion-reduce:transition-none`（`CopyButton` 已示范）。

| 禁止项 | 原因 |
|---|---|
| 任何**长于 400ms 的装饰性动画** | 拖沓（`AnimatedNumber` 的 800ms 是**数据补间**、不是装饰，属例外） |
| **多个元素同时飞入**（staggered 逐项进场） | 长列表里等于灾难（滚动时反复触发），本库一律不做 |
| 无意义的循环动画 / 只靠动画传达状态 | 呼吸灯、闪烁、无限旋转一律禁止（真正的 loading 指示除外）；动画只是补充，状态必须有静态可辨的视觉（颜色 + 文字） |
| 动 `width` / `height` / `margin` 等布局属性 | 触发逐项重排；`Card interactive` 明确只用 `transform` + `box-shadow` |
## 1.7 图标
来源统一 `lucide-react`（`^1.38.0`）。
### 1.7.1 尺寸阶梯（**禁止默认 24px**）
Lucide 默认 `size=24`，**必须显式给尺寸**，否则与周围 16px 文字严重不匹配。

| 场景 | 类 | 值 | 出处 |
|---|---|---|---|
| 行内 / 按钮内 | `size-4` | 16px | `Button` 基类、`StatCard` 图标、`MorphingDialogClose`、`SelectTrigger` / `SelectItem`、`TabsTrigger`、`AccordionTrigger`、`Calendar` 箭头 |
| 代码块复制、复选框勾、图表图例 | `size-3.5` | 14px | `CodeBlock` / `JsonViewer` 的 `copyIconClassName="size-3.5"`、`Checkbox` 的 `Check` |
| 徽标内、图表 tooltip 指示 | `size-3` / `size-2.5` | 12 / 10px | `Badge`（`[&_svg]:size-3`）、`JsonViewer`、`ChartTooltipContent` |
| 导航项 | 随容器 | 由 `size-10` / `md:size-12` 按钮承载 | `DockNav`（`<Icon strokeWidth={2} />`） |
| 纯图标按钮容器 / 空态大图标 | `size-8` / `size-9`（内含 `size-4`）；大图标 `size-8` | 32 / 36 / 32px | `Button size="icon-sm" / "icon"`、`IconButton`；空态与错误态见 3.3 |
### 1.7.2 strokeWidth
**统一 `strokeWidth={2}`**（`DockNav` 显式写出，其余走 Lucide 默认 2）。不要混用 1.5 / 2.5——细线在大屏发虚，粗线在小号糊成一团。
例外：`Checkbox` 的 `Check` 用 `strokeWidth={3}`（16px 见方的勾需更粗才看得清）；`Sparkline` 的 `strokeWidth = 1.5` 是**图表折线**参数，不属图标规范。
### 1.7.3 图标与文字间距
| 场景 | 间距 |
|---|---|
| 按钮内 / 字段标签 / `TabsTrigger` 内 | `gap-2`（8px，`Button` 基类）/ `gap-2` / `gap-1.5` |
| 徽标内图标—文字 | `gap-1`（4px） |
| 统计卡标签—图标 | `justify-between` 推到两端，不给 gap |

**纯图标按钮必须有可访问名**：`aria-label`（`CopyButton` 内置 `aria-label="复制"`）或 `tip`（`IconButton` 自动套 Tooltip）——至少一个。
## 1.8 无障碍基线
### 1.8.1 焦点环写法（统一，不要自创）
```
outline-none focus-visible:ring-2 focus-visible:ring-ring/50 focus-visible:border-ring
```

| 组件 | 真实写法 |
|---|---|
| `Button` | `outline-none focus-visible:ring-2 focus-visible:ring-ring/50 focus-visible:border-ring` |
| `Input` / `Switch` | `focus-visible:border-ring focus-visible:ring-2 focus-visible:ring-ring/30`（Switch 为 `/40`） |
| `Select` / `Tabs` / `Accordion` / `Checkbox` / `Calendar` 单元格 | `focus-visible:outline-none focus-visible:ring-[3px] focus-visible:ring-ring/50` |

规则：① **只用 `focus-visible`**，不用 `focus`（鼠标点击不该出环）；② 保留 `outline-none` 再用 `ring` 重建——**只写 `outline-none` 是把键盘用户的路断掉**；③ 环色一律 `ring-ring`（跟随主色），透明度 30%–50%，同页内保持一致；④ 全局兜底 `globals.css` 里 `* { @apply border-border outline-ring/50 }`。
### 1.8.2 键盘可达性
| 要求 | 说明 / 出处 |
|---|---|
| 所有交互元素可 Tab 到 | 用真 `<button>` / `<input>`，不要 `<div onClick>` |
| Esc 关闭 + Tab 焦点锁 + 关闭后焦点还给触发器 | `MorphingDialogContent` 全部内置（`triggerRef.current?.focus()`）；Radix 系（Select / Popover / Tabs / Accordion）自带 Esc 与焦点管理 |
| 自定义可点 div 补键盘 | `MorphingDialogTrigger` 的做法：`role="button"` + `tabIndex={0}` + `Enter` / `Space` + `aria-haspopup` / `aria-expanded` / `aria-controls` |
| 日历进 Popover 要 `autoFocus` | 否则键盘用户要多 Tab 一次才进得去 |
| 拖拽要键盘可用 / 选中态要有语义 | 用 `SortableList`（`@hello-pangea/dnd` 自带键盘拖拽与读屏支持），不要手搓 HTML5 DnD；`DockNav` 用 `aria-current={isActive ? 'page' : undefined}` |
### 1.8.3 点击目标最小尺寸
| 场景 | 最小 | 出处 |
|---|---|---|
| 标准 / 小按钮 | `h-9` / `h-8`（36 / 32px） | `Button` default / `sm`、`SelectTrigger size="sm"` |
| 纯图标按钮 | `size-8` / `size-9`（密集操作**至少 `size-8`**） | `Button size="icon-sm"`、`IconButton` |
| 导航项 / 日历单元格 | `size-10`（`md:size-12`）/ `--cell-size: --spacing(8)` = 32px | `DockNav` / `Calendar` |
| 复选框 | `size-4`（16px）+ **需用 `Label` 关联扩大可点区** | `Checkbox` |
| 弹窗关闭 | `size-7`（28px，下限） | `MorphingDialogClose` |

**移动端**：可点元素间距 ≥ 8px。`DockNav` 移动端 `gap-1`（4px）+ `size-10` 是**导航专用**的紧凑做法，不要照搬到普通按钮列表。
### 1.8.4 颜色不作为唯一信息载体
反例 → 正确做法：红点表示「失败」→ `Badge variant="destructive"` 写「失败」；金额下跌只标红 → `StatCard` 的 `trend` 同时给 `↑` / `↓` 与百分比；必填只靠红框 → `FieldError` 给文字且 `FieldLabel` 联动变红（`group-data-[invalid=true]/field:text-destructive`）；图表多系列只靠颜色 → `ChartLegend` + `ChartTooltip` 给名字（`config[key].label`）；复选靠底色区分选中 → `Checkbox` 选中态有勾图标（`Check` / indeterminate 方块）。
辅助文本（`title` / `aria-label`）也不能替代可见文字标签。

# 二、组件规范（Components）
## 2.1 外壳
| 组件 | 用途 | 真实 Props | 规则与变体 | 禁忌 | 无障碍 |
|---|---|---|---|---|---|
| `UIKitProvider` | **应用根节点必须先包的一层**：一次装好「主题 + Tooltip + 吐司」三件套 | `children`（✅）、`themeProps?: { defaultTheme?: 'light'\|'dark'\|'system'; storageKey?: string }`（默认 `storageKey='theme'`）、`toasterProps?`（sonner 原生 props）、`tooltipDelay?: number`（默认 300） | 内部顺序 `ThemeProvider > TooltipProvider > (children + Toaster)`；只在应用根**渲染一次** | ❌ **漏包 = 白屏**：控制台只报一句 `Tooltip must be used within TooltipProvider`（`AppShell` / `DockNav` / `IconButton` 内部都用了 Tooltip，这是最容易踩的上手坑，`providers/kit.tsx` 就是为收口它而存在）；❌ 包在某个子页面里（切页即报错） | 无（容器组件） |
| `AppShell` | 应用外壳 = 导航 + 顶栏（Logo / 会滚动切换的页面名 / 右侧动作）+ 内容区 | `children`（✅）、`nav`（✅，通常传 `<DockNav />`）、`title: string`（✅）、`logo?`、`previousTitle?`（判动画方向）、`actions?` | 布局用 **grid** `md:grid-cols-[auto_1fr] md:grid-rows-[auto_minmax(0,1fr)]`，**`minmax(0,1fr)` 不可省**（否则内容区撑破行高、滚不起来）；一屏**只有一个**外壳，切页只换 `title` + `children`；内容区自带 `flex min-h-0 w-full min-w-0 flex-1 flex-col overflow-hidden` | 外层不要再包 `max-w-*`（宽度由自己 `max-w-6xl` 管）；不要嵌套外壳 | `title` 必给（页面可见 H1 语义位） |
| `DockNav` | 悬浮胶囊导航（本套 UI 的门面）。手机底部居中横排，`md` 起变左侧竖排吸顶 | `items: DockNavItem[]`（✅，`{ id, label, icon: LucideIcon }`）、`value: string`（✅）、`onChange: (id) => void`（✅）、`onPrefetch?: (id) => void`、`className?`、`ariaLabel?`（默认 `'主导航'`） | 两个滑块：激活 `bg-sidebar-primary`（跟当前页）、悬浮 `bg-sidebar-accent`（跟鼠标）；**改尺寸必改两个数**：移动端步长 `2.75rem`（`size-10` + `gap-1`）、桌面端 `3.75rem`（`md:size-12` + `md:gap-3`），写死在 `--nav-offset-x/y`；**首次进导航必须先让悬浮滑块在不可见状态下瞬移再淡入**（`flushSync` + `getBoundingClientRect()`），否则会看到一条横线扫过——这段逻辑不要重构掉；项数 **3–7** | 不要写 `bg-primary` / `text-foreground`（有自己的 sidebar 令牌）；不要做多层导航；不要让胶囊溢出滚动；项不允许只有图标 | 容器 `aria-label` + 每项 `aria-label` / `title` + `aria-current="page"` + `onFocus` / `onTouchStart` 触发 prefetch |
| `PageHeader` | 内容区顶部条 = 左标题 / 描述 + 右动作 | `title: ReactNode`（✅）、`description?`、`actions?`、`className?` | **硬规矩**：容器 `flex flex-none flex-wrap items-center justify-between gap-2`；标题列 `min-w-0` + 文字 `truncate`（**只截断自己**）；动作列 `shrink-0` + `whitespace-nowrap`（**永不缩、永不折**）；同页多组「标题 + 按钮」**必须都用 `PageHeader`** 保证左右边缘对齐 | ❌ 标题不 `truncate` → 长标题把按钮挤到第二行，整行高度跳变（踩过的坑） | `description` 会被截断，不要承载唯一关键信息 |
## 2.2 数据展示
| 组件 | 用途 | 真实 Props | 规则与变体 | 禁忌 | 无障碍 |
|---|---|---|---|---|---|
| `StatCard` | 统计卡 = 图标 + 标签 + 大数字（补间滚动）+ 可选单位 / 趋势 / 脚注 | `label: string`（✅）、`value: string \| number \| undefined`（✅）、`unit?`、`icon?: LucideIcon`、`trend?: number`（≥ 0 向上绿，< 0 向下红）、`footer?`、`className?`、`glow?: boolean`（默认 `true`） | **值 / 单位必须分开传**（见 1.2.3）；一张卡只表达**一个指标**；一屏 ≤ 4 张 | ❌ 给 `value` 传已带单位的字符串（`"1.23M$"`——单位会掉进大号字里，量级视觉不齐）；❌ 传日期或非数值文本（`AnimatedNumber` 会 `parseFloat` 后补间）；❌ **关 `glow`**（本套 UI 的「通透感」一大半来自它） | trend 的 `↑` / `↓` 是文字、读屏可读——这正是它必须和颜色一起存在的原因 |
| `MetricTabs<T>` | 分段切换（segmented control），选中项背后有滑动底（`layoutId` 共享布局） | `options: { value: T; label: string; badge?: string \| number }[]`（✅）、`value: T`（✅）、`onChange: (v: T) => void`（✅）、`className?` | 选项 **2–5 个**；`badge` 用 `text-[10px] tabular-nums` | ❌ 用于 > 5 个（那是 `Select` 的活）；❌ 用于导航（那是 `DockNav`） | 泛型 `T extends string`；当前只有视觉选中态，**复杂场景需自行补 `role="tablist"` / `role="tab"` / `aria-selected`** |
| `VirtualizedList<T>` | 长列表虚拟滚动，只渲染视口内的行 | `items: T[]`（✅）、`renderItem: (item, index) => ReactNode`（✅）、`estimateSize?: number`（默认 `56`）、`overscan?: number`（默认 `8`）、`getItemKey?: (item, index) => string \| number`（强烈建议给）、`gap?: number`（默认 `0`）、`footer?`、`className?` | **容器必须有确定高度**（父层 `h-full` 或 `flex-1 min-h-0`）；**> 100 条必须虚拟化**，≤ 50 条直接 `map`；`estimateSize` 给接近真实值的估值；`gap` 会被加进 estimate，行自身**不要**再写 `mb-*`；每行须有稳定唯一 key | ❌ 父层不给高度（全列表一次性渲染，**且不报错**，最阴的坑）；❌ 行序号当 key（头部插入时全量 key 变更 → 实测高度缓存失效 → 抖动）；❌ 行内做被 `transform` 影响的自定义测量 | 未渲染的行**对读屏不可见**——列表要让用户知道总数（底部 `Badge` 或 `footer` 写「共 N 条」）；键盘上下移动需业务补 |

## 2.3 图表与日历
**`ChartContainer` 族**——recharts 封装，把 `config` 的色值按主题注入成 CSS 变量 `--color-<key>`，双主题图表**不需要在 JS 里读当前主题**。

| 组件 | Props | 说明 |
|---|---|---|
| `ChartContainer` | `config: ChartConfig`（✅）、`children`（recharts 图）、`id?`、`className?`、`initialDimension?` | `initialDimension` 默认 `{ width: 320, height: 200 }`：容器测出真实尺寸前的兜底，防首帧高度塌成 0 |
| `ChartTooltip` | = recharts `Tooltip` | 直通 |
| `ChartTooltipContent` | `indicator?: 'line' \| 'dot' \| 'dashed'`（默认 `'dot'`）、`hideLabel?`、`hideIndicator?`、`nameKey?`、`labelKey?` | 底 `border-border/50 bg-background shadow-xl` |

`ChartConfig` 真实形状：`Record<string, { label?: ReactNode; icon?: ComponentType } & ({ color?: string; theme?: never } | { color?: never; theme: { light: string; dark: string } })>`。

```tsx
const config = { tokens: { label: '消耗',
  // 同一支令牌给两个主题：值只写一次，主题切换由 CSS 变量接管
  theme: { light: 'var(--chart-2)', dark: 'var(--chart-2)' } } } satisfies ChartConfig

<ChartContainer config={config} className="aspect-auto h-52 w-full">
  <AreaChart data={data}>
    <CartesianGrid vertical={false} />  <XAxis dataKey="day" tickLine={false} axisLine={false} />
    <ChartTooltip content={<ChartTooltipContent />} />
    <Area dataKey="tokens" stroke="var(--color-tokens)" fill="var(--color-tokens)" fillOpacity={0.25} />
  </AreaChart>
</ChartContainer>
```

**规则**：图上各处**只写 `var(--color-<key>)`**，不要写 hex / oklch 字面量；recharts 内部元素（轴刻度文字 / 网格 / 光标 / 活动圆点）的中性色覆盖写在 `base.css` 的 `@layer base` 里，全部以 `var(--令牌)` 取值，所以**不逐个配颜色也会与主题一致**；出图前给容器定高（`h-52` / `aspect-auto`）；系列数 ≤ 5（`--chart-1..5`）。
**禁忌**：⚠ **单独用 recharts 原生组件不会继承令牌色**，必须走 `ChartContainer`——绕开它，图表在深色下会变成默认蓝紫。
> ⚠ **recharts 类名坑（本库修过的一个真 bug）**：recharts 2 与 3 的内部类名不同——2 是**下划线式**（`.recharts-cartesian-axis-tick_text`），3 是**连字符式**（`.recharts-cartesian-axis-tick-value`）。
> 用错版本的选择器**不报错、静默失效**：刻度字会一直是 recharts 自带的 `#666`，深色主题下几乎看不清，而且完全不跟主题走。
> 所以改动这些选择器后，**别用肉眼看**——用 `getComputedStyle` 实测渲染色（深浅两套各测一遍）。

**`Calendar` / `CalendarDayButton`**——日历 / 日期选择（react-day-picker 封装）。

## 2.5 原子件
### `Button`
**真实 Props**：`variant`、`size`、`asChild`（默认 `false`）+ `ComponentProps<'button'>`。共享 `focus-visible` 环 + 禁用态 + `150ms` 过渡。

| `variant` | 真实类（要点） | 用在哪 |
|---|---|---|
| `default` | `bg-primary text-primary-foreground hover:brightness-110 active:scale-[0.98] shadow-sm` | 常规主操作 |
| `gradient` | `bg-linear-to-r from-primary to-accent hover:brightness-110 shadow-md hover:shadow-lg` | 页面**唯一**的关键 CTA |
| `secondary` | `bg-secondary text-secondary-foreground hover:brightness-105` | 次一级操作 |
| `outline` | `border border-border bg-transparent hover:bg-secondary/60` | 有边界感的次级操作 |
| `ghost` | `hover:bg-secondary/60 hover:text-foreground` | 无边界操作（工具条） |
| `destructive` | `bg-destructive/10 text-destructive border border-destructive/25 hover:bg-destructive hover:text-destructive-foreground` | 危险操作 |
| `link` | `text-primary underline-offset-4 hover:underline` | 文字按钮 |

| `size` | 真实类 | 值 |
|---|---|---|
| `sm` | `h-8 px-3 text-xs` | 32px |
| `default` | `h-9 px-4` | 36px |
| `lg` | `h-10 px-6 text-base` | 40px |
| `icon` | `size-9 p-0` | 36×36 |
| `icon-sm` | `size-8 p-0` | 32×32 |

**规则**：**一屏最多一个 `gradient`**；图标—文字 `gap-2`、图标 `size-4`；同排时主操作在右（`PageHeader` 的 `actions`）；与 `Input` 同排用 default（都是 `h-9`，不错位）。**禁忌**：❌ 用 `Button` 做纯图标按钮（用 `IconButton`）；❌ 用 `destructive` 做非危险操作；❌ 手动加 `w-*`（基类有 `shrink-0` + `whitespace-nowrap`）。**无障碍**：`<button type="button">`；焦点环 `ring-2 ring-ring/50`；禁用要用 `disabled` 属性（不是只加 `opacity` 类）。
### `Badge`
**真实 Props**：`variant`、`asChild` + `ComponentProps<'span'>`。胶囊 `rounded-full px-2 py-0.5 text-xs`；soft 风格（色底 `/15` + 同色文字），深色下比实心耐看；内置图标 `size-3`、`gap-1`。

| `variant` | 真实类 | 用途 |
|---|---|---|
| `default` | `bg-primary/15 text-primary` | 中性主色标记 |
| `secondary` | `bg-secondary text-secondary-foreground` | 次级标记 |
| `outline` | `border-border text-foreground` | 无底色、有描边 |
| `success` | `bg-emerald-500/15 text-emerald-700 dark:text-emerald-400` | 成功 / 启用 |
| `warning` | `bg-amber-500/15 text-amber-700 dark:text-amber-400` | 警告 / 待处理 |
| `destructive` | `bg-destructive/15 text-destructive` | 失败 / 停用 |
| `muted` | `bg-muted text-muted-foreground` | 未知 / 不适用 |

**注意**：`success` / `warning` 用的是 **Tailwind `emerald` / `amber` 字面色**，不是令牌（`tokens.css` **没有** `--success` / `--warning`）——换极端品牌色时这两处要单独复核。浅色下取 `700` 档（`600` 在暖象牙底上只有 3.1:1，不达 AA），深色下取 `400` 档。**禁忌**：文案 **2–4 字**（`已启用` / `失败`），它是徽标不是句子；不放句子、不换行（`whitespace-nowrap`）。**无障碍**：状态徽标必须带文字（不能只有色块）。
### `Card` 族
**用途**：内容容器。**真实 Props**：`Card` 有 `glow?: boolean`（默认 `false`）、`interactive?: boolean`（默认 `false`）；其余为 `ComponentProps<'div'>`。

| `Input` | `ComponentProps<'input'>`（`type` 直通） | `h-9 rounded-lg border-input bg-transparent px-3 text-sm shadow-xs`；焦点 `focus-visible:border-ring focus-visible:ring-2 focus-visible:ring-ring/30`；选中 `selection:bg-primary selection:text-primary-foreground`；`h-9` 与 Button 默认尺寸对齐，同排不错位 | ❌ 靠 `placeholder` 代替 `Label`；错误态要给 `aria-invalid`（触发 `aria-invalid:border-destructive aria-invalid:ring-destructive/20`）配 `FieldError`。无障碍：`<input>` + `<Label htmlFor>` 必须成对 |
| `Label` | `ComponentProps<typeof LabelPrimitive.Root>` | `flex items-center gap-2 text-sm font-medium leading-none select-none`；禁用联动 `group-data-[disabled=true]:opacity-50` | **必须 `htmlFor` 关联控件**，不要用 `<div>` 冒充标签 |
| `Separator` | `orientation?`（默认 `'horizontal'`）、`decorative?`（默认 `true`） | `bg-border`；水平 `h-px w-full`、竖直 `h-full w-px` | **独立分隔区段用它**，不要手写 `<div className="border-t" />`；容器内部分隔用 `border-border/60` 更轻 |
| `Switch` | `ComponentProps<typeof SwitchPrimitive.Root>`（`checked` / `onCheckedChange` / `disabled`） | `h-5 w-9 rounded-full`；选中 `bg-primary`、未选 `bg-input`；Thumb `size-4` + `shadow-sm`，选中 `translate-x-4`、未选 `translate-x-0.5` | ❌ 用它表达「保存后才生效」（它暗示即时应用），那种用 `Checkbox`。无障碍：Radix 自带 `role="switch"` + `aria-checked`，需配 `Label` |
| `Progress` | Radix Root，`value` 传 **0–100** | 轨道 `h-2 rounded-full bg-muted`；填充 `bg-linear-to-r from-primary to-accent` + `transition-transform duration-300`，用 `translateX(-(100-value)%)` 实现（**不动 width**） | ❌ `value` 传 0–1；❌ 在条上叠文字（需要就放旁边） |
| `Toaster` | `ToasterProps`（sonner 原生） | 内置 `theme={resolvedTheme}`、`position="top-center"`、`--normal-bg: var(--popover)`、`--normal-text: var(--popover-foreground)`、`--normal-border: var(--border)`、`--border-radius: var(--radius)`；**根布局渲染一次** | ❌ 多层级渲染多个 `Toaster`（重复弹）；❌ 让它离开 `ThemeProvider`（深色不跟随） |
### `Select` 族
**用途**：下拉选择。**选项数量分档选用**：≤ 4 个**别用 Select**（用 `MetricTabs` / `Tabs`，一眼看全比点开更好）；5–20 个用 Select；> 20 个在 Select 上再加搜索输入框。

| 组件 | 真实 Props（要点） |
|---|---|
| `Select` / `SelectGroup` / `SelectValue` | Radix Root / Group / Value 透传 |
| `SelectTrigger` | `size?: 'sm' \| 'default'`（默认 `'default'`；`h-8` / `h-9`）+ Radix Trigger |
| `SelectContent` | `position?`（默认 `'popper'`）、`align?`（默认 `'start'`）；`z-50 rounded-lg bg-popover shadow-md` |
| `SelectItem` / `SelectLabel` / `SelectSeparator` | Radix 透传；`SelectLabel` 为 `text-xs text-muted-foreground` |
| `SelectScrollUpButton` / `SelectScrollDownButton` | 由 `SelectContent` 内部自动渲染 |

**规则**：`SelectTrigger` 有 `data-[placeholder]:text-muted-foreground`；选中项右侧显 `Check`（`SelectItem` 内置）。
**禁忌（关键坑）**：⚠ **必须给 `SelectItem` 显式 `value`，且不能是空字符串**——Radix 用空串表示「未选择」，给空串会导致选中状态失效（表单里表现为「选了又弹回去」）。
**无障碍**：Radix 自带 `role="combobox"` / `listbox` 与全套键盘（`↑↓` 移动、`Enter` 选、`Esc` 关）；需配 `Label`；错误态给 `aria-invalid`。
### `Checkbox`
**用途**：复选（多选、批量操作、表头全选）。**真实 Props**：`ComponentProps<typeof CheckboxPrimitive.Root>`（`checked` / `onCheckedChange` / `disabled`；支持 `checked="indeterminate"`）。
**规则**：`size-4 shrink-0 rounded-[4px] border-input`；选中与 indeterminate 均 `border-primary bg-primary text-primary-foreground`；勾 = `<Check className="size-3.5" strokeWidth={3} />`，indeterminate = `size-2` 方块。
**禁忌**：❌ 用它做**互斥选择**（那是 RadioGroup，或选项 ≤ 4 时用 `MetricTabs`）——Checkbox 的语义是「可以多选」。
**无障碍**：Radix 自带 `role="checkbox"` + `aria-checked`（含 `mixed`）；16px 太小，**必须用 `Label` 包住或 `htmlFor` 关联以扩大可点区域**。
### `Tabs` 族
**用途**：标签页。

| 组件 | 真实 Props（要点） |
|---|---|
| `Tabs` | Radix Root（`defaultValue` / `value` / `onValueChange`）；容器 `flex flex-col gap-3` |
| `TabsList` | `variant?: 'default' \| 'line'`（默认 `'default'`） |
| `TabsTrigger` | Radix Trigger；**必须给 `value`** |
| `TabsContent` | Radix Content；需 `value`，与 Trigger 一一对应 |

**两个变体**：`default` = `h-9 gap-1 rounded-lg bg-muted p-1`，选中项 `bg-raised text-raised-foreground font-semibold shadow-sm`（用抬升面「浮起来」，比纯色块更贴合本库柔光气质）；`line` = `gap-4 border-b border-border p-0`，选中项下方 2px `border-primary` 指示线——**适用于嵌在卡片头部里的场景**。
**禁忌**：⚠ 每个 `TabsTrigger` **必须给 `value`** 且与 `TabsContent` 一一对应——**缺一个该面板就永远点不开**。超过 5 个标签页改用 `Select` 或左侧导航。
**无障碍**：Radix 自带 `role="tablist"` / `tab` / `tabpanel` 与 `←→` 切换；`TabsContent` 有 `focus-visible` 环。
### `Popover` 族
**用途**：锚定在触发元素旁的浮层（筛选面板、日期选择容器、行内设置）。

| 组件 | 说明 |
|---|---|
| `Popover` | Radix Root（受控 `open` / `onOpenChange`） |
| `PopoverTrigger` | 触发元素 |
| `PopoverAnchor` | 自定义锚点（内容定位到它而非触发器） |
| `PopoverContent` | `align?`（默认 `'center'`）、`sideOffset?`（默认 `6`）；`z-50 w-72 rounded-lg border-border bg-popover p-3 text-popover-foreground shadow-md`；进出场 fade + zoom + `slide-in-from-*` |

**选用规则（与 `MorphingDialog` 的分工）**：轻量、就地、不打断 → `Popover`（如「筛选」「选择日期」）；要展示主体内容、用户会沉浸其中 → `MorphingDialog`（如点开一条日志看详情）。
**禁忌**：**Popover 不要再套 Popover**（浮层叠两层，用户按 Esc 不知道该关哪个）；日期选择放进 Popover 要给 `Calendar` `autoFocus`。
**无障碍**：Radix 自带 Esc 关闭、点外部关闭、焦点管理；`PopoverContent` 有 `outline-none`（焦点环需按需补）。
### `Accordion` 族
**用途**：折叠面板（表单分区、设置项分组、长文档目录）。

| 组件 | 真实 Props（要点） |
|---|---|
| `Accordion` | Radix Root；`type="single"` + `collapsible` 或 `type="multiple"` |
| `AccordionItem` | `border-b border-border last:border-b-0` |
| `AccordionTrigger` | `py-3 text-sm font-medium`，hover → `text-primary`，展开时箭头 `rotate-180` |
| `AccordionContent` | `overflow-hidden text-sm`；进出用 `animate-accordion-up` / `animate-accordion-down`（tw-animate-css） |

**选用**：`type="single"` + `collapsible` 适合设置页（同时只展开一段，视线不散）；`type="multiple"` 适合对照查看。
**注意**：表单里用 Accordion 时 **收起的面板内容仍在 DOM 中**（Radix 只做视觉收起），所以提交不会丢字段——比手写 `display:none` 省事，但**因此不要用它做「大数据量列表的懒加载」**。
**无障碍**：Radix 自带 `aria-expanded` / `aria-controls` / `region`，键盘 `Enter` / `Space` / `↑↓` 可用；`AccordionTrigger` 有完整焦点环。
### `Tooltip` 族
**用途**：提示气泡。**真实 Props**：`TooltipProvider` 的 `delayDuration` 默认 `200`；`TooltipContent` 的 `sideOffset` 默认 `6` + `side` / `align` 透传。
**规则**：`z-50 rounded-md bg-foreground px-2.5 py-1 text-xs text-background`，纯 CSS 三角箭头（跟随主题）；进出场 `animate-in fade-in-0 zoom-in-95`。`TooltipProvider` 在根布局套一次。
**禁忌**：**不要把关键信息只放 tooltip**（触屏无 hover）；**不要在 tooltip 里放交互元素**（Radix 要求内容非交互）。
**无障碍**：触发元素需要有可访问名。
### `MorphingDialog` 族
**用途**：形变弹窗。触发器与弹窗**共用同一个 `layoutId`**，motion 插值位置与尺寸——列表卡片「就地放大」成弹窗，关掉缩回原位。

| 组件 | 真实 Props | 说明 |
|---|---|---|
| `MorphingDialog` | `children`、`transition?: Transition` | 推荐 `{ type: 'spring', bounce: 0.2, duration: 0.4 }` |
| `MorphingDialogTrigger` | `children`、`className?`、`style?`、`triggerRef?` | 打开时自动换等尺寸占位（`visibility: hidden`） |
| `MorphingDialogContainer` | `children` | portal 到 `document.body`，`z-50`，居中，`max-w-lg`，背板 `bg-black/40 backdrop-blur-md` |
| `MorphingDialogContent` | `dismissOnClickOutside?`（默认 `true`）、`ignoreOutsideClick?: (event) => boolean`、`className?`、`style?` | `role="dialog"` + `aria-modal="true"` |
| `MorphingDialogClose` | `children?`、`className?`、`onClose?` | 默认 `×`，`size-7`，右上角 |
| `MorphingDialogTitle` / `MorphingDialogDescription` | `children`、`className?` | `font-semibold` / `text-sm text-muted-foreground` |

**已内置（不要重复实现）**：Esc 关闭、焦点锁弹窗内（Tab 首尾循环）、打开锁 body 滚动、关闭把焦点还给触发器、点外部关闭（默认放行 `select` / `popover` / `tooltip` 的 portal 层）。
**两个关键实现细节（别省）**：① 打开时触发器换成**等尺寸普通占位元素**（`visibility: hidden`）而非 motion 元素，否则会「闪回」抽动一下；② 关闭时用 `AnimatePresence` 包住容器，让缩回动画播完再卸载。
**禁忌**：❌ 去掉 `MorphingDialogContainer`（`Content` 必须在它里面才能 portal）；❌ `ignoreOutsideClick` 写成「一律返回 true」（弹窗关不掉）；❌ 同屏多个弹窗复用同一触发器元素（`layoutId` 打架）。
**无障碍**：`role="dialog"` + `aria-modal` + 触发器的 `aria-haspopup` / `aria-expanded` / `aria-controls` + 关闭按钮 `aria-label="关闭"`。**每个弹窗必须有 `MorphingDialogTitle`**（否则读屏报「无标题对话框」）。

# 三、模式规范（Patterns）
## 3.1 页面骨架：三段式
```
AppShell（nav + logo + title + actions）
└─ main（min-h-0 min-w-0 flex-1 flex-col overflow-hidden）
   ├─ PageHeader（标题行：左标题/描述 + 右动作）
   └─ 内容区（flex-1 min-h-0，自己滚 或 交给 Virtualized*）
```

**根节点接入（先包这一层，否则白屏）**：

```tsx
// main.tsx
createRoot(document.getElementById('root')!).render(
  <UIKitProvider themeProps={{ defaultTheme: 'system' }}>
    <App />
  </UIKitProvider>,
)
```

```tsx
<AppShell
  nav={<DockNav items={NAV} value={page} onChange={setPage} onPrefetch={prefetch} />}
  title={TITLES[page]} previousTitle={prevTitle}            // 后者判方向动画
  actions={<Button variant="gradient">新建</Button>}
>
  <PageHeader title="请求日志" description="近 24 小时"
    actions={<><Button variant="outline" size="sm">导出</Button><Button size="sm">刷新</Button></>} />
  <div className="mt-3 min-h-0 flex-1">
    <VirtualizedList items={logs} estimateSize={44} gap={4} renderItem={…} getItemKey={(i) => i.id} />
  </div>
</AppShell>
```

**标题行硬规矩**：标题列容器 `min-w-0`（允许 flex 子项收缩，默认 `min-width:auto` 会拒绝收缩）；标题文字 / 描述 `truncate`（自己截断成省略号）；动作列容器 `flex shrink-0 items-center gap-1 whitespace-nowrap`（**永不缩、永不折**）。踩过的坑：标题一长就把按钮挤到第二行，整行高度跳变，整个页面在长标题下抖一下。**同类区块对齐**：同一页里两处「标题 + 按钮」（如日志页的「筛选」与「结果」两组）**必须都用 `PageHeader`**；手写两套 flex 几乎必然错开 1–2px。
## 3.2 表单
**组合层级（严格照抄）**：

```
FieldSet（gap-4）└─ FieldGroup（gap-5）└─ Field（一个字段行，gap-2）
   ├─ FieldLabel（htmlFor；内部可嵌 FieldDescription）
   ├─ Input / Select / Switch / Checkbox …（id 与 htmlFor 对应）
   └─ FieldError（errors 或 children；紧跟控件）
```

**错误展示**：① 位置在**控件正下方**（不要只放表单顶部做汇总，除非表单很长——那时顶部汇总 + 行内都放）；② 视觉 = `FieldError` 的 `text-xs text-destructive` + 输入框 `aria-invalid` 触发 `border-destructive`；③ 标签联动 = `Field` 给 `data-invalid="true"`（或控件 `aria-invalid`）→ `FieldLabel` 变红；④ 多错误传 `errors` 数组（以 `；` 连接）；⑤ 无错误时 `FieldError` **返回 `null`**——不要自己写占位 `<div>`，否则行高会跳。

| 校验时机 | 做什么 |
|---|---|
| 首次进入 | **不校验**，所有字段静默（不要一进来就满屏红） |
| 字段失焦（blur） | 校验该字段，立即给 `FieldError` |
| 提交时 | 校验全部；失败则聚焦第一个出错字段 |
| 输入中（onChange） | **只清除已有错误**，不新增（输入中报错会让人打字打到一半就挨骂） |

必填标记放 `FieldLabel` 里（如「名称 \*」），不要只靠红框。
**提交按钮位置**：① 一屏内的表单 → 按钮在**右下**（`flex justify-end gap-2`，主操作在右）；② 很长的表单 → **底部固定一行**（`sticky bottom-0 bg-background/80 backdrop-blur` + 上边 `Separator`），否则用户要滚到底才能提交；③ 取消在左、提交在右；④ **危险操作不要和提交并排**（隔一个 `FieldSeparator` 或换行）。
## 3.3 空态 / 加载态 / 错误态
本库**没有** `Skeleton` / `EmptyState` / `ErrorState`，一律用已有件组合，不要新造一套视觉。

```tsx
// 空态：图标 + 主文案 + 一句下一步，三者缺一不可
<div className="flex min-h-40 flex-col items-center justify-center gap-2 text-center">
  <Inbox className="size-8 text-muted-foreground" />
  <div className="text-sm font-medium">还没有日志</div>
  <div className="text-xs text-muted-foreground">发起一次请求后，这里会出现记录</div>
  <Button variant="outline" size="sm" className="mt-1">去测试</Button>
</div>
```

| 场景 | 怎么做 |
|---|---|
| 统计卡首次加载 | `value={undefined}` → `AnimatedNumber` 显示 `-`（本库默认占位） |
| 列表首次 / 追加加载 | 首次：`Card` 包 3–5 个 `animate-pulse bg-muted` 块做骨架（**高度要与真实行一致**，否则加载完页面跳）；追加：`VirtualizedList` / `VirtualizedGrid` 的 `footer` 放「加载中…」，`VirtualizedGrid` 配 `onReachEnd` |
| 局部刷新 | 该区域 `opacity-60` + `pointer-events-none`，**不要**整页 loading 遮罩 |
| 按钮提交中 | `disabled` + 左侧 `Loader2`（`size-4 animate-spin`）+ 文案改「处理中」 |
| 页面级加载失败 | 中央块 = `AlertTriangle`（`size-8 text-destructive`）+ 主文案 + **两个动作**：「重试」（`Button`）+「查看详情」（`Button variant="outline"`，开 `MorphingDialog` 放 `RequestDetail`） |
| 行级错误 | 行内 `Badge variant="destructive"` + 该行文字 `text-destructive`；行可点开 `MorphingDialog` 看 `RequestDetail` |
| 操作失败 | `toast.error('保存失败', { description })`（`CopyButton` 的失败分支就是这个写法） |

**铁律**：错误文案**必须给下一步**（重试 / 去哪看详情 / 改什么），不能只说「出错了」。不要用转圈的整页遮罩（丢上下文）。
## 3.4 弹层层级
| 层 | 组件 | 层级 | 怎么用 |
|---|---|---|---|
| 内容 | 页面内容 | 自动 | — |
| 就地浮层 | `Popover` | `z-50` | 轻量、就地、不打断：筛选面板、日期容器、行内设置 |
| 提示 | `Tooltip` | `z-50` | 只作**辅助说明**（触屏无 hover） |
| 轻提示 | `Toaster`（sonner） | 自带（`top-center`） | 操作结果反馈：`toast.success('已保存')` |
| 详情 / 确认层 | `MorphingDialog` | `z-50`（背板 + `max-w-lg`） | **列表 → 详情**的首选，也从卡片「就地放大」 |

| 场景 | 用哪个 |
|---|---|
| 列表点开看完整详情（渠道详情、请求排障） | **`MorphingDialog`**（`RequestDetail` 放进 `MorphingDialogContent`） |
| 确认类操作（删除、停用） | **`MorphingDialog`**（`Title` + `Description` + 两个 `Button`）。**不要用 `window.confirm`** |
| 表单编辑（3–8 字段） | **`MorphingDialog`**；大表单 / 多段长流程改独立页面，不要塞弹窗 |
| 筛选 / 选日期 / 行内设置 | **`Popover`**（`Calendar` 记得 `autoFocus`） |
| 图标含义 / 字段说明；操作结果 | `Tooltip`（`IconButton` 的 `tip`）；`toast`（`Toaster`） |

**层级规矩**：① **不要弹窗套弹窗**（第二层要么并进第一层，要么走独立页面）；② 弹窗内能用 `Tooltip` 与 Radix 的 select / popover（`defaultIgnoreOutsideClick` 已放行 `[data-slot="tooltip-content"]` 等）；③ 弹窗内的下拉**必须**渲染在 portal 里（否则点下拉会被判成「点外部」而关掉弹窗——这正是该守卫存在的原因）；④ **同时最多一个弹层**（tooltip / toast 这类无焦点的除外）；⑤ `Toaster` 在根布局只渲染一次；⑥ Popover 不套 Popover，Accordion 不套 Accordion。
## 3.5 长列表 / 卡片墙
| 数据量 | 怎么做 |
|---|---|
| ≤ 50 条 | 直接 `map`，不要虚拟化（测量与 key 成本更高） |
| 50–100 条 | 视行高与渲染成本定；有重内容（图表 / 图片 / memo 组件）就用虚拟化 |
| **> 100 条** | **必须用** `VirtualizedList` / `VirtualizedGrid` |
| 有实时追加（日志流） | 必须虚拟化，且 `getItemKey` 用稳定业务 id |

**容器必须有确定高度（硬要求）**：

```tsx
// ✅ 正确定高：h-full / flex-1 min-h-0 / h-[calc(100dvh-12rem)]
<div className="flex-1 min-h-0"><VirtualizedList … /></div>

// ❌ 没有高度：虚拟化静默退化、全量渲染，且不报错
<div><VirtualizedList … /></div>
```

**卡片墙（`VirtualizedGrid`）额外要求**：① `columns` 断点按 1.3.3（**`lg` = 960px**）；② `estimateItemHeight` 给接近真实的估值；③ 触底加载 = `onReachEnd` + `reachEndEnabled={hasMore}` + `reachEndOffset`（默认 1 行）+ `footer={<div>加载中…</div>}`；④ 窄容器（< 640px）用 `layout="list"` 强制单列，不要硬压两列。
**键（key）规矩**：一律 `getItemKey={(item) => item.id}`；日志这类无 id 的用「时间戳 + 序号」组合。**禁用数组下标**——头部插入新数据时缓存全失效、间距抖动。
## 3.6 请求排障：`RequestDetail` 的三条设计规矩
| # | 规矩 | 为什么 | 真实实现 |
|---|---|---|---|
| 1 | **多行原样展示** | 提示词 / 请求体压成一行等于没法看（换行是语义的一部分） | `whitespace-pre-wrap break-all font-mono text-xs leading-relaxed` |
| 2 | **curl 与 body 分开复制** | 有时只要 curl 复现，有时要把 prompt 单独拿去改 | 两块各自带 `CopyButton`（「请求体」+「curl（可直接执行）」） |
| 3 | **超过 14 行折叠** | 一个超长 prompt 会把整页撑爆 | `content.split('\n').length > 14` → `maxHeight: 260`（`collapsedHeight`）+ 内部滚动；`collapsedHeight={0}` 关闭折叠 |

```tsx
// 排障场景标准解
<MorphingDialog transition={{ type: 'spring', bounce: 0.2, duration: 0.4 }}>
  <MorphingDialogTrigger>{rowCard}</MorphingDialogTrigger>
  <MorphingDialogContainer>
    <MorphingDialogContent className="max-h-[80vh] overflow-y-auto bg-card p-5">
      <MorphingDialogTitle>请求详情</MorphingDialogTitle>
      <MorphingDialogClose />
      <RequestDetail
        fields={[{ label: '模型', value: 'gpt-5.1', mono: true },
                 { label: '耗时', value: formatTime(ms).formatted },
                 { label: '状态码', value: 200 }]}
        request={{ method: 'POST', url, headers, body }}
        response={responseText}
      />
    </MorphingDialogContent>
  </MorphingDialogContainer>
</MorphingDialog>
```

**规矩**：`fields` 只放**短**键值对（模型 / 耗时 / 状态码 / token）；`mono: true` 给 id、URL 这类等宽更易读的值；超长内容一律进 `CodeBlock`。

# 四、内容规范（Content）
| 项 | 规矩 |
|---|---|
| 人称 | **不用「我 / 我们」**；直接说事（「已保存」而不是「我帮你保存好了」） |
| 语气 | 平实陈述句。不卖萌、不堆感叹号 |
| 术语 | 与后端 / 代码里的名词一致（叫「渠道」就一直是「渠道」，不要时而「供应商」） |
| 时态 | 完成后用完成态：「已保存」「已删除」「已复制」 |
| 中英混排 | 专有名词用原文（API、token、curl），不硬翻成「接口密钥」这类自造词 |
| 标点 | 中文全角；短文案句末**不加句号** |
| 长度 | 按钮 ≤ 4 字；提示 ≤ 20 字；说明 ≤ 40 字 |
## 4.1 按钮文案
**动词开头**，2–4 字：`新建` / `保存` / `删除` / `导出` / `刷新` / `重试` / `去测试`。**禁止** `确定` / `好的` / `提交`（确认弹窗里尤其要说清动作：`删除渠道` 而不是 `确定`）。危险操作**写清对象**（`删除渠道`、`清空日志`）。两个按钮不要都凑动词（`是 / 否` → 改 `删除渠道 / 取消`）。进行中改「处理中」「保存中」并 `disabled`。
## 4.2 空态 / 错误文案模板
**空态**：`主文案：还没有{对象}`（「还没有日志」）+ `副文案：{做什么}后，{会出现什么}`（「发起一次请求后，这里会出现记录」）+ `动作（可选）：去{做什么}`。三条硬要求：① 说明**为什么空**（不是「暂无数据」这种零信息）；② 给**下一步**；③ **不指责用户**（不说「你没有配置任何东西」）。
**错误**：模板 `{什么}失败：{原因}。{下一步}`——操作失败 `保存失败` + `description: 名称为空`；加载失败 `日志加载失败` + 「重试」按钮；校验失败直接说**怎么改**（`名称不能为空`、`必须是 1–64 个字符`）；网络 / 上游保留关键信息（`上游返回 429：请求过于频繁`）。**禁忌**：`出错了` / `未知错误` / 裸错误码 / 把 `JSON.stringify(error)` 塞进 toast。
## 4.3 数字、金额与时间
| 项 | 规矩 | 工具 |
|---|---|---|
| 金额 | 单位 `$` / `K$` / `M$` / `B$`，**统一 2 位小数** | `formatMoney(n).formatted` |
| 计数 | 单位空 / `K` / `M` / `B` | `formatCount(n).formatted` |
| 精确值（明细 / 导出） | `1,234,567` | `withThousands(n)` |
| 耗时 | 单位 `ms` / `s` / `m` / `h` / `d` | `formatTime(ms).formatted` |
| 百分比 | 保留 1 位小数 + 符号（`+4.2%` / `-1.8%`），带 `↑` / `↓` | `StatCard` 的 `trend` |
| 全部数字 | `tabular-nums` | 类名 |
| 时间 | 相对（列表 / 日志）：`N 分钟前` / `N 小时前` / `N 天前`，7 天以上转绝对；绝对（详情）：`YYYY-MM-DD HH:mm:ss`，仅日期 `YYYY-MM-DD`；一律**本地时区**展示，接口给 UTC 的要转换后再展示，**不要界面写 UTC 却不标** | — |

# 五、扩展与换肤
## 5.1 新增组件的步骤
1. **选层**：`ui/`（无业务原子件）/ `shell/`（外壳）/ `data/`（数据展示）/ 根 `components/`（通用件）。
2. **只吃令牌，不吃字面量**：颜色用 `bg-primary` / `text-muted-foreground` / `border-border`（**禁止 hex、禁止 `text-gray-500`、禁止 `bg-[#xxx]`**）；圆角按 1.4.1 决策；阴影只用 1.5.2 档位；时长用 `--duration-*`（**禁止硬编码 `0.4s`**，弹窗 spring 例外）；间距只用 1.3.1 档位。
3. **接 `cn()`**：所有可覆写处写 `className={cn(默认类, className)}`——用户才能用 `className="bg-red-500"` 覆盖（`twMerge` 让后写的同类工具类生效）。
4. **加 `data-slot="<name>"`**：库内组件全带（`data-slot="button"` / `"card"` / `"select-content"` …），用于外部样式钩取与弹窗的 portal 放行判断（`defaultIgnoreOutsideClick` 就依赖这类选择器）。
5. **补无障碍与四态**：真语义元素（`button` / `input` / `label` / `dl`）、`focus-visible` 环（照抄 1.8.1）、可访问名、`role` / `aria-*`；hover / `focus-visible` / `active` / `disabled` 四态；动效遵守 1.6.3。
6. **导出并验证**：在 `src/index.ts` 对应分组 `export`（相关 `type` 一起导出，如 `ResponsiveColumns`、`DockNavItem`）；`npm run typecheck` 必须 0 错误；在 `preview/App.tsx` 加一屏演示（同时是类型回归载体）；**浅色 / 深色两套都看一遍**。
7. **依赖只加一次 radix**：统一用 `radix-ui` 聚合包，**不要**再装 `@radix-ui/react-*` 单包（混装两套 radix 是这类项目最常见的坑：类名与样式各走一套，主题化直接失控）。
8. **内部导入一律相对路径**：`src/` 内**不得出现 `@/` 别名**（消费者项目里没有你的别名，装上就解析失败）。这条是「可安装包」成立的前提，改成相对路径后 `tsc` 必须 0 错误。

**第 2 步自查**：把新组件 `grep` 一遍 `#`、`rgb(`、`hsl(`、`oklch(`、`shadow-`、`duration-`、`[`（任意值），逐个确认来自令牌。
## 5.2 换肤三个层次
### 层次 1：只换主色（5 分钟）
改 `tokens.css` 里的 **3 个值 × 浅深两套 = 6 处**：

```css
:root {
  --primary: <主色浅色值>;  --accent: <强调色浅色值>;  --ring: <与 primary 同值>;
}
html.dark, .dark {
  --primary: <主色深色值>;  --accent: <强调色深色值>;  --ring: <与 primary 同值>;
}
```

**必须一起复核的（否则有色偏残留）**：
- `--sidebar-primary` / `--sidebar-ring`：浅色下 `--sidebar-primary` 是**浅钢蓝**（`oklch(0.7200 0.0750 248.0000)`）而非 `--primary`（`0.5000`），要决定导航激活滑块是否跟着换；深色下两者同值。
- `Badge` 的 `success` / `warning` 用的是 **Tailwind `emerald` / `amber` 字面色**（不是令牌）——极端品牌色下要单独复核。
- `base.css` 里 `body::before` 的柔光光斑是品牌蓝（`oklch(0.68 0.05 232)`）、`body::after` 是它的浅一档（`oklch(0.78 0.03 240)`），这两个是**字面值**（刻意不进令牌：它们是环境光，不参与语义）。
- `ThemeProvider` 的 `THEME_COLOR`（`light: '#e5ecf2'`, `dark: '#1e1b19'`）是移动端状态栏色，与 `--background` 对应，改底色时要一起改（还有 `index.html` 的 `<meta name="theme-color">`）。
### 层次 2：换整套明暗色（半天）
按 1.1.1 的分组重填 `:root` 与 `html.dark, .dark` 的全部色令牌，并遵守：

| 约束 | 要求 |
|---|---|
| 色彩空间 | 保持 **oklch**（亮暗两端只调 L 通道就能得到视觉等重的颜色，这是这套色板可维护的关键） |
| 色温铁律 | 中性色全员暖带（55°~95°）、品牌与图表冷色落冷带（248°~258°）；**不要**给中性色加冷色相，否则卡内元素会与暖卡底发脏 |
| 明暗关系 | 深色**不是**浅色的简单反色，是各自调过的一整套（浅色暖象牙、深色暖炭），并且**暗端也取暖**，只保留品牌蓝一个冷点 |
| 图表五色 | 主序列保持**同色相递降亮度**（L 递减），对比序列换暖带色相（拉开冷暖），**不要**换彩虹配色 |
| `--destructive` | 浅色 `oklch(0.55 0.15 30)`（深红，当文字/描边色）、深色 `oklch(0.84 0.12 30)`（**浅珊瑚红**）。深色下若沿用深红当文字色，暗底上实测只有 2.4:1，看不清——本库按与 `primary` 同构的规则映射（暗底取浅红面色 + 深棕字） |
| 对比度 | 按 1.1.2 复核（正文 ≥ 7:1、次要 ≥ 4.5:1） |
| 侧栏 | 8 个 sidebar 令牌独立填，允许与主区深浅不同 |
### 层次 3：换形态（1 天+）
| 想改什么 | 改哪里 | 注意 |
|---|---|---|
| 圆角整体大小 | `--radius` 与 `--spacing` | `--radius` 一改，`sm/md/lg/xl/2xl` 全跟着（`calc` 链）；`Calendar` 的 `--cell-size` 跟 `--spacing(8)` |
| 间距节奏 | `--spacing` | 影响所有 `p-*` / `gap-*` / `size-*`，改前先看 1.3.1 与 1.3.2 |
| 阴影浓淡 / 动效节奏 | 8 个 `--shadow-*` / 4 个 `--duration-*` | 阴影保证深色下不发灰；组件只引用变量，改令牌即全站生效 |
| 导航形态 | `DockNav` 源码 | **改尺寸必改两个数**：移动端步长 `2.75rem`、桌面端 `3.75rem`（写死在 `--nav-offset-x/y`） |
| 柔光背景 / 滚动条策略 | `globals.css` 的 `body::before/::after`、`* { scrollbar-width: none }` | 去掉柔光页面立刻变平（改时保留 `pointer-events: none`）；全站隐藏滚动条，所以**内容区必须有别的「还有更多」暗示**（底部渐隐 / 总条数 `Badge`） |

**换肤验收**：浅色 + 深色各把 `preview/` 过一遍，重点看：① 图表（`--chart-*` 是否够区分）；② `Badge` 的 success / warning；③ 焦点环可见性；④ `Tooltip`（`bg-foreground` / `text-background` 互换后是否还清楚）；⑤ `Select` / `Popover` 浮层底与主区是否有足够层次差。
