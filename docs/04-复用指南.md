# 04 · 复用指南（在新项目里怎么用）

四种方式，按投入从低到高。**方式 B 是实测跑通的那条**（用 Vite + React 19 搭一个消费者工程，照本指南接线即可）。

---

## 方式 A：只抄设计令牌（5 分钟换肤）

不改组件代码，只把"长相"搬过去。任何用 Tailwind v4 的项目都能用。

1. 把 `src/styles/tokens.css` 与 `src/styles/base.css` 复制到新项目；
2. 入口 CSS 里按顺序引：`tailwindcss` → `tw-animate-css` → `tokens.css` → `base.css`；
3. 暗色靠 `<html class="dark">`（class 策略，不是 `prefers-color-scheme`）；
4. 原来的 `bg-gray-100` / `text-slate-500` 逐步换成语义类 `bg-background` / `text-muted-foreground`。

> Tailwind **v4 没有 `tailwind.config.js`**，主题全在 CSS 的 `@theme inline` 块里。新项目若是 v3，要么改写令牌为 v3 的 `theme.extend`，要么升级到 v4。

---

## 方式 B：装包（★推荐，已实测）

```bash
# 1. 把包放进新项目
cp inkstone-ui-0.1.0.tgz 新项目/
# 2. 加依赖
"dependencies": { "inkstone-ui": "file:./inkstone-ui-0.1.0.tgz" }
npm install
```

然后**只要三处接线**：

```ts
// ① vite.config.ts —— 把库排除出依赖预打包
export default defineConfig({
    plugins: [react(), tailwindcss()],
    optimizeDeps: { exclude: ['inkstone-ui'] },
})
```

```css
/* ② 你的入口 CSS —— 引令牌与基础层，并让 Tailwind 扫到库里用到的工具类 */
@import "tailwindcss";
@import "tw-animate-css";
@import "inkstone-ui/styles/tokens.css";
@import "inkstone-ui/styles/base.css";
@source "../node_modules/inkstone-ui/src";
```

```tsx
/* ③ 根节点包一层 UIKitProvider（主题 + Tooltip + 吐司都在里面） */
import { UIKitProvider } from 'inkstone-ui'
createRoot(document.getElementById('root')!).render(
    <UIKitProvider><App /></UIKitProvider>,
)
```

之后业务里只认包名，不碰库内文件：

```tsx
import { AppShell, DockNav, PageHeader, VirtualizedList, RequestDetail, Button, Badge } from 'inkstone-ui'
```

**三处各漏了会怎样（都是实测过的症状）**：

| 漏了 | 症状 |
|---|---|
| `optimizeDeps.exclude` | 构建/启动报 JSX 语法错误 —— 库以源码形式发布，不能被当成预打包产物 |
| CSS 里的 `@source` | **能构建、不报错，但页面变成裸样式**（Tailwind v4 默认不扫 `node_modules`，库里的 `bg-card` 之类没人生成） |
| `UIKitProvider` | **整个应用白屏**，控制台只有 `Tooltip must be used within TooltipProvider` |

⚠ 不要在新项目里再装一份不同大版本的 `react` / `react-dom`：本库把它们声明为 `peerDependencies`，用的是你项目里那一份。装完 `npm ls react` 应该只有一个版本。

## 方式 C：拷源码目录（不经包）

不想走包管理时，把库的 `src/` 整个拷成新项目的一个目录（如 `src/ui-kit/`），再给它配一条别名指向自己：

```ts
// 前提：先把库内相对路径保持原样（本库内部已是相对路径，无需改动）
resolve: { alias: { 'inkstone-ui': path.resolve(__dirname, 'src/ui-kit/index.ts') } }
```

好处是改起来最直接（可以直接在项目里改库代码）；代价是升级时要手动同步。

## 还需要别的原子件时（别再混装 radix）

**本库已覆盖**（`ls src/components/ui/` 实测 19 个文件）：`accordion` `badge` `button` `calendar` `card` `chart` `checkbox` `field`（族）`input` `label` `morphing-dialog` `popover` `progress` `select` `separator` `sonner`（= `Toaster`）`switch` `tabs` `tooltip`。

**没有的**（别以为有）：`dialog`（普通居中弹窗 —— 用 `morphing-dialog`）、`alert`、`skeleton`、`empty-state`、`dropdown-menu`、`context-menu`、`radio-group`、`slider`、`table`、`sheet`、`avatar`、`textarea`。要补有两条路：

1. **照本库的写法自己加一个**（推荐，见 07 §5.1）：从 `radix-ui` 聚合包取命名空间 + 用本库令牌写样式。这样不会多装依赖、样式与 1.4/1.5 规范一致。
2. 用 shadcn CLI 生成后**改造**：`npx shadcn@latest add dropdown-menu`。它会给你的 `package.json` 塞进 `@radix-ui/react-dropdown-menu` 单包，并把类名写成 shadcn 默认值 —— 必须手动换成 `radix-ui` 聚合包并把色值/圆角改成令牌，否则就是"两套 radix 混装 + 配色对不上"的老毛病。

## 二开注意事项

1. **`cn()` 是唯一类名合并入口**，别用模板字符串拼类名。
2. `@theme inline` 里的映射**必须有 `inline`**，否则 Tailwind 在 `var()` 链上取不到值。
3. 暗色变体由 `@custom-variant dark (&:is(.dark *))` 定义 —— **class 策略**，不是媒体查询。
4. 补充色（`success` / `warning`）是相对 `--primary` 的色相微调，改主色时要一起改，否则深色下显脏；改完明暗两态各过一眼对比度（正文 ≥ 4.5:1）。
5. 改 `DockNav` 尺寸时**必须同步改注释里那两个步长**（横 `2.75rem` / 竖 `3.75rem`），否则滑块错位。
6. 任何新的长内容块都走 `CodeBlock`（已处理多行、复制、折叠）。
7. **库内不许出现 `@/` 别名**：消费者项目里没有你的别名，装上就解析失败；内部导入一律相对路径，改完 `npm run typecheck` 必须 0 错误。
8. 新增组件若用到 Radix 的 Tooltip，别忘消费者侧已有 `UIKitProvider` 兜着；但**用到别的 Provider**（如 `HoverCard`）时，要一并加进 `UIKitProvider`，否则又是白屏级别的坑。
